Actual commands used

Example: configuration A

# Set parameters on test PostgreSQL instance
psql -d pgbench_test -c "ALTER SYSTEM SET shared_buffers = '256MB';"
psql -d pgbench_test -c "ALTER SYSTEM SET work_mem = '4MB';"
brew services restart postgresql@18

# Measure transaction throughput (repeat 3 times)
pgbench -c 10 -j 2 -T 30 -P 5 pgbench_test

# Optional: show one live test without changing settings
python3 quick_benchmark.py

# View captured results
python3 graph.py results_new.csv
Important: tuner.py modifies PostgreSQL instance-wide settings and restarts the service. Use only on a separate local test database; not on a production server.

Experiment design

  • Database: pgbench_test (initialized at scale factor 10)
  • Tested: shared_buffers = 128, 256, 512 MB; work_mem = 4 or 16 MB.
  • Workload: 10 simultaneous clients; 2 threads; 30-second tests; fixed pgbench built-in transactions.
  • Iterations: 3 per configuration; total 18 readings.
  • Metric: TPS, transactions processed per second. Higher TPS implies better throughput for the same workload.
  • Decision: average the 3 runs and select the highest observed mean TPS.
More memory does not always mean more TPS. The default performed best in this experiment, but results can change across machines and workloads.

1-minute presentation script

Use this while switching between dashboard and interactive lab

Good morning. Our DBMS project is a PostgreSQL Database Settings Tuner. PostgreSQL performance depends on configuration, so our Python program automatically compares different memory settings.

We tested six combinations of shared_buffers and work_mem. For every setting, the program restarts PostgreSQL, runs pgbench three times, and records transactions per second.

Here on the dashboard, the highest observed average is 25,248 TPS for the default setting. In the interactive lab, I can choose any configuration and show its three recorded results. I can also replay how the tuner evaluates all 18 trials.

Our conclusion: database tuning should be based on measurement. Increasing memory does not necessarily increase performance for every workload.

The dashboard and replay show existing recorded measurements. Actual new benchmarking uses the included tuner.py script locally.

Common teacher questions

Q. What is a database tuner?

A program that tests database configuration settings and compares their measured performance.

Q. What is TPS?

Transactions per second: the number of transactions processed in one second. Higher TPS means greater throughput for a comparable workload.

Q. What does shared_buffers do?

It controls memory PostgreSQL uses as a shared buffer cache for database pages.

Q. What does work_mem do?

It limits memory available per eligible sorting or hashing operation before PostgreSQL may need temporary disk space.

Q. Why did default win?

It had the highest observed average in these tests. We cannot claim it is best for every server, query mix, or hardware setup.

Q. What is the algorithm?

Grid search: test each of six configurations three times, compute the mean TPS, and choose the highest observed mean.
